# Contributing

When contributing to this repository, please first discuss the change you wish to make via issue, email, or any other method with the owners of this repository, ensuring you follow the [Code of Conduct](https://github.com/Airscripts/awesome-steam-deck/blob/main/CODE_OF_CONDUCT.md).

## Curation Criteria

Awesome Steam Deck is a curated list. Relevance to Steam Deck alone does not guarantee inclusion.

Preference is given to resources that are authoritative, original, established, actively maintained, or uniquely useful to Steam Deck users. A submission should add clear value beyond what is already present in the list.

Commercial, editorial, or affiliate-supported resources are not automatically excluded, but they are evaluated using the same criteria. If you are affiliated with a submitted website, product, project, or service, please disclose that relationship and any relevant monetization in the issue or pull request.

Single-purpose buying guides, promotional pages, or resources created primarily for exposure or backlinks may be declined when they do not provide enough original or distinctive value.

Original testing, measurements, compatibility data, technical research, tools, databases, or other Steam Deck-specific information are stronger signals for inclusion.

## Software And User Safety

Software submissions that can materially affect user security, privacy, system stability, or data should demonstrate reasonable maturity and independent usage before being included.

This is especially relevant for software that:

* Runs background services;
* Performs network activity or downloads;
* Accesses personal data or credentials;
* Requires elevated privileges;
* Changes system configuration;
* Communicates with external APIs or cloud services.

Maintainers may consider signals such as ongoing development, issue history, independent users, community feedback, documented usage, transparent source code, and a track record of maintenance.

There is no fixed minimum number of stars, downloads, or users, and these metrics alone do not guarantee inclusion.

Very new or unvalidated projects may be asked to gain more real-world usage and community validation before being reconsidered.

Final inclusion remains at the maintainers' discretion in order to keep the list useful, trustworthy, and curated.
